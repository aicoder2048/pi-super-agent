# option-ta 构建汇报

日期：2026-11-17。结论：完成本轮P2模块包及能过检查的最简工具；不是完整第一版上线，不移植theta计算代码。

## 成品

模块目录：`<状态目录>/modules/option-ta/`

完整能力、默认及未完成清单：上述目录的 `README.md`。

按用户指定说明书、术语表、税务memo第14节、P1接口记录、四封虚构成交回信及build plan已定范围构建：

- full模板；五专家＋会诊反方，领队流程技能，五段正式分析输出。
- 六份知识来源；`knowledge/glossary/glossary.md`与提供术语表逐字节一致，`license=bundled`、`authority=reference`。
- 五工具、五技能、三个feed、四道eval、七集合。原六集合保留；补private `market-snapshots`承接年末快照目标，合计两shareable、五private。
- 四封虚构.eml与提供文件逐字节一致，保留原expected并标明手写未来验收草稿；不是解析器通过证据。
- 私密集合不开放工具；stock-ta外部uses只在对应专家；只传必要代码，缺席降级，内部原文不可读则转述“请对 stock-ta 说”。

## 真实最简能力

- 基本JSON、代码、日期、数量与价格校验。
- strategy对给定逐腿方向、价格文字、数量、已核实乘数，用万分之一美元整数计算未扣费权利金现金流；不默认乘数100，不代表完整策略或Roll能力。
- record只返回`VALIDATED_ONLY`、`may_write=false`，不查重、不授权入账。
- chain、vol、ledger及三个feed明确`NOT_IMPLEMENTED`；ledger未读库；feed不写记录、不推进cursor，并返回可见problem。没有用空结果或零收益假装完成。

### 模型预演：未全过

实际跑三轮 `just module try option-ta`，每轮四题，自动判分均为3/4、退出码1。不能汇报全部PASS。

1. 首轮税务题漏报QCC状态：补税务章节14.1/14.2/14.3定位及逐项回应核对要求。
2. 第二轮税务内容已完整，但`QCC待确认`与期望`QCC 待确认`空格不同而误判；将这一断言拆为术语和状态分别匹配，保留题目内容要求。
3. 最终轮：邮件边界、税务边界、stock-ta边界PASS；现金流题FAIL的唯一打印原因是没有原样短语“未扣费”。实际答复为“费用未知、未扣除”，金额均正确：BTC -63.7500、STO +60.1000、合计 -3.6500 USD。人工语义复核认为该处为措辞匹配问题，但机器结果仍为3/4；此判题脆弱点留待后续改进并复跑，没有伪称全过。

stock-ta题实际得到缓存结构和20条信号，不是实时行情。测试答复称跨模块两次仅传`{"symbol":"NVDA"}`，未传虚构账户/持仓/成本；未另做完整调用轨迹审计。未测试quote、earnings-date或全部提供方环境。预演临时状态目录由命令清理。
