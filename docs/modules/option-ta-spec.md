# option-ta 说明书（草稿）

给模块工坊的访谈用。格式和工坊访谈写的 `spec.md` 一致。术语见 `option-ta-glossary.md`，税务口径见 `option-ta-tax-memo.md`，已定的范围和门槛见 `option-ta-build-plan.md`，期权接口的实测见 `option-ta-p1/README.md`（P1，2026-11-17）。标「（待定）」的项等使用者拍板。

## 名字和说明

- 名字：`option-ta`
- 中文标题：期权分析
- 队名：期权研究组
- 给幕僚长的一句话（不超过 60 字）：美股期权的链、隐含波动、希腊值、策略盈亏和你的期权成交：开仓、Roll、平仓、到期、指派；问股价涨跌和技术面的归 stock-ta

## 管什么

- 期权链快照：某个标的某个到期日附近的行权价、买卖价、IV、希腊值、未平仓量。
- 波动率状况：平值 IV、IV 和历史波动率之比、IV rank 和百分位、期限结构、偏斜。标的加进期权自选时，用期权日线回填最近一年的 IV；之后每天收盘后存一份。口径见「IV 历史」。
- 策略计算：给定一组腿，算权利金、盈亏平衡、到期盈亏、年化收益、被指派概率。数字由代码算，模型只转述。
- 期权成交记录：STO、BTO、BTC、STC、Roll（三种），以及到期、指派、行权，外加被指派产生的股票和买方行权交割的股票（第一版范围 B，2026-11-16 使用者定）。股票的其余买卖不记。按账户记，按合约和交易链汇总。每笔仓位带意图（十个意图之一）。
- 两种视图：交易链盈亏（成败看赢的金额），税务视图（只打标记，不自动扣减）。第一版从记下的期权能判的照判：期权之间的 wash sale、价差两腿的跨式。要独立股票批次或持有期的判断（合格备兑 call、股票和期权的跨式、§1233 买 put 视为卖空、涉及股票的 wash sale）一律标「待确认」，以后补要哪些数据见 tax memo 第 14.3 节。和 1099-B 对账以后再做。
- 主动提醒：到期临近、接近或穿过行权价、权利金达标、到期前的财报和除息（门槛见 build plan；本说明书补了两处细节，见「主动提醒的两处细节」）。

## 不管什么

- 股价涨跌、K 线和技术面：归 stock-ta。
- 仓位管理：现金、保证金、仓位大小、组合配置。
- 下单：只给分析和提醒，不下单。
- 裸卖 call、蝶式、铁鹰等多腿组合（第一版）。
- 基于 IV 的机会提醒（第二版）。
- 报税本身：只给标记（和 1099-B 对账以后加），不是税务建议。

## 五个典型问题

1. 「QQQ 下周五到期，600 附近的 put 现在什么价，IV 多少？」
2. 「我那 10 张 SPY 650 put 现在赚了几成？要不要提前买回？」（按意图回答）
3. 「把 NVDA 12 月 140 的 CSP 往后 Roll 一个月、行权价降到 135，净收多少？」
4. 「卖了 2 张 TSLA 12/18 300 call，2.10，收租。」（记一笔成交）
5. 「今年到现在，期权一共赢了多少钱？按交易链列一下。」

## 事实从哪里来

- **期权行情**：Massive（Polygon）接口。期权链快照 `/v3/snapshot/options/<标的>`、合约列表 `/v3/reference/options/contracts`、合约日线 `/v2/aggs/ticker/O:...`。2026-11-14 实测使用者的 key 能读，带 greeks、IV、OI、报价；字段、缺字段和分页见 P1。取数规则见「行情取数规则」。stock-ta 不开放期权数据，option-ta 自己取。
- **正股趋势、关键价位、现价**：任务里的专家调 stock-ta 开放的工具（「外部工具」一节）。`watch` feed 要现价时自己调 Massive（「密钥」一节）。
- **财报日**：任务里的专家调 stock-ta 开放的 `earnings-date`。`watch` feed 要财报日发提醒，自己调 Finnhub。
- **除息日**：Massive `/v3/reference/dividends`（P1 已实测，字段够用）。只查得到已宣布的除息；没宣布的按「预计除息日」推算，见下一节。
- **成交**：券商交易台的成交回信（经工作邮箱重定向进 Gmail，再经宿主的 `mail` 连接器），加使用者手动说的。按订单（合约、方向、成交日、账户）记累计成交的增量，部分成交也记，数以邮件为准，含糊就问。解析规则见「成交邮件（`fills`）」。
- **领域知识**：使用者自己的规则（意图表、门槛，来自拷问记录）、税务 memo；theta 的研究摘要只作参考，进包前逐篇查版权，只留转述和链接；公共规则引用 OCC、CBOE 等权威出处。
- **不能编的**：价格、IV、希腊值、日期、行权价、张数、金额、税务规则的出处。

## 密钥

按 `docs/modules/architecture/connectors-and-secrets-design.md`（C1、C2）、ADR-0029、ADR-0031：
- Gmail 授权是身份类密钥，归宿主的 `mail` 连接器。option-ta 的 `fills` feed 用这个连接器，只收 `brokers` 名单上的发件人，不碰 Gmail 密钥，包里也不点名它。
- Massive、Finnhub 是业务类密钥，放 option-ta 自己的 `modules-data/option-ta/.env`，用 `just module secret option-ta POLYGON_API_KEY`、`just module secret option-ta FINNHUB_API_KEY` 写进去。值可以和 stock-ta 的一样，两个模块各存一份。
- 为什么 option-ta 要自带：期权链、合约日线、除息 stock-ta 不开放；`iv`、`watch` 两个 feed 要行情和财报日，可 feed 的处理代码不经网关，调不了外部工具（设计稿规则 11）。任务里的专家调 `stock-ta/tools/quote`、`earnings-date` 时，宿主按被运行的提供方取 key，用的是 stock-ta `.env` 里那一份（ADR-0031）。
- 额度：Massive 和 Finnhub 各是一份额度。option-ta 自己的调用、经开放工具的调用、stock-ta 自己的 feed 和任务都从里面扣，宿主不排队（设计稿规则 4「额度」）。会诊把一次问答变成几次调用，额度用得更快。

## 模板

`full`：要算东西、存数据、有 feed。

- feeds：
  - `fills`：`"connector": "mail"`，`settings.senders` 写本模块的集合名 `"brokers"`。`brokers` 每行一个文字字段 `address`，写地址或 `@域名`，可选 `addedAt`、`removedAt`，写法同 `mail` 的邮件名单（ADR-0029）。名单写交易台的发信地址（信经重定向进来，发件人还是交易台，见「成交邮件（`fills`）」）。不在包里直接写地址列表：包会进公开仓库，地址看得出在哪家券商开户；地址只由领队写进私密集合 `brokers`。`reads` 带 `fills`。handler 把交易台的成交回信解析成成交行，写进私密集合 `fills`，不经过模型。
  - `iv`：收盘后给期权自选的每个标的存一行 IV 原始输入，用 option-ta `.env` 里的 Massive 密钥。标的刚加进期权自选时，先回填最近一年。存什么、怎么算见「IV 历史」。每个交易日只存一次：`every` 写短间隔，cursor 记已经存过的交易日，当天存过就直接回空，写法照 stock-ta 的 `feeds/scan/index.ts`（cursor 带 `date`，用 `lastSession` 按模块自己的日历算最近一个已收盘交易日，同一交易日不重扫）。
  - `watch`：交易时段按门槛检查记下的仓位，发提醒或开任务。现价、期权报价、除息用 Massive 密钥，财报日用 Finnhub 密钥，都自己取，因为 feed 调不了外部工具（设计稿规则 11）。
  - `watch` 的提醒带持仓细节，全文发到使用者自己的 Telegram（2026-11-17 使用者接受）。宿主只按 `into` 判 feed 私密不私密（`src/modules/manifest.ts` 的 `feedClass`）：`watch` 不写 `into`，算非私密，虽然它 `reads` 私密的 `fills`、`chains`，提醒原文（合约、张数、权利金进度）照样全文进 Telegram。
- data（括号里先写集合的 `class`）：
  - `fills`（`private`）：原始成交和事件，按账户。ADR-0029 要求 mail feed 的 `into` 是私密集合。被指派产生的股票也记在这里：`side` 是 BUY 或 SELL，`caused_by_event` 指向那次指派或行权（tax memo 第 14.1 节），不另建股票集合。
  - `chains`（`private`）：交易链和 Roll 组，意图和改意图的记录。
  - `accounts`（`private`）：匿名键，不存真实账号。
  - `brokers`（`private`）：成交邮件的发件人名单，见 `fills` feed。
  - `iv-snapshots`（`shareable`）：每个标的每个交易日一行 IV 原始输入，回填和日常同一形状（「IV 历史」）。
  - `watchlist`（`shareable`）：期权自选，初始为空，只由领队写入。
  - 两个 `shareable` 都是 2026-11-17 使用者定的。
- 有 `private` 集合带来两条后果：
  - option-ta 不能开放任何工具（设计稿规则 7）。别的模块调不了 `chain`、`vol`、`strategy`。
  - option-ta 是私密使用方（ADR-0030「风险」）。它的任务可能把私密内容放进参数，调会联网的 `stock-ta/tools/quote`（发给 Massive）、`earnings-date`（发给 Finnhub），内容就出了本机。今天这两个工具只收股票代码，路很窄，宿主不检查参数。专家技能写明只给它们传标的代码。
- tools：`chain`（期权链快照）、`vol`（波动率状况）、`strategy`（策略计算）、`record`（校验一笔成交、按 `fill_id` 查重）、`ledger`（交易链和税务视图；1099-B 对账以后加）。每个工具带 `cases.json`，覆盖休市、缺字段、应答体 `status: "ERROR"`，以及 HTTP 429 和 5xx。后两项靠宿主回放夹具带 HTTP 状态和响应头，#171 已支持。
- 工具不写集合。`record` 只校验和查重，交回规整好的一行；真正写进 `fills` 的是领队调 `data/fills`。
- 工具读集合的行（`record` 查重、`ledger` 汇总）：只读打开 `$PSA_MODULE_DATA/data.db`，表名就是集合名，宿主的行号在 `_id` 列。写法照 mail 的 `tools/draft-reply/index.ts`。

## 行情取数规则（P1 实测，2026-11-17）

适用于读期权链和合约的工具（`chain`、`vol`、`strategy`）和 `iv`、`watch` 两个 feed。

- **滤掉二元期权。**合约列表和链快照里混着 `O:B1...` 开头的二元期权，没有 IV 和希腊值，按代码排序时排在最前面。只留 `details.ticker` 以 `O:<标的>` 开头、且 `exercise_style` 是 `american` 的行。将来做指数期权（SPX 是 european）时这条要改。
- **按行权价范围取。**只看某个行权价附近时，带 `contract_type`、`expiration_date`、`strike_price.gte/.lte`，一页就够。
- **跟分页。**应答带 `next_url` 就还有下一页，取下一页要再带一次 `Authorization` 头。最大痛点、GEX、OI 墙要整条链，SPY 一个周到期日约 3 页。工具交给专家的仍是算好的紧凑结果，不是原始行。
- **缺 IV 和希腊值不当 0。**近月深度价内、极度价外的合约常常没有 `implied_volatility`，`greeks` 是空对象。工具用报价中间价按 BS 自算，标「自算」；没有报价（bid、ask 都是 0）或反解不收敛，标「无数据」。自算和供应方的值不混在一列里比较。
- **报价为 0、当天没成交**：`bid` 为 0、`last_trade` 和 `day` 是空对象都是正常状态，照实标出，不报错。
- **异常成交只用一个成交量来源**：合约日线 `/v2/aggs/ticker/O:.../range` 的 `v`。今天和历史均量都从这里取。快照的 `day.volume` 和日线差约 1.5%，不和日线混用。
- **休市时的 IV 不是收盘 IV。**休市时期权报价停在收盘，正股价和供应方的 IV、希腊值跟着盘前盘后的正股价继续变。休市时给出的 IV 和希腊值标「休市」并写明取数时刻；`iv` feed 不存供应方的 IV。
- **正股价延迟 15 分钟**（`underlying_asset.timeframe: DELAYED`），期权报价是实时的。按正股价判断的提醒照此对齐时刻，见下一节。

## 主动提醒的两处细节（2026-11-17）

门槛仍以 build plan 为准，这里只补 P1 带出的两处：

- **到期日开盘离行权价不到 3%**：在美东 09:45 以后的第一次检查判断。09:30 读到的正股价还是盘前价。
- **除息**：已宣布的除息，按原门槛（卖出的 call 在价内、到期前有除息，除息前 2 个交易日响铃）。还没宣布的，用「预计除息日」同样判断，但只静音提醒，提醒里标「预计、未宣布」。正式宣布后改按已宣布的处理。`watch` feed 每个交易日重查一次除息接口，发现已宣布就换。

预计除息日怎么推：

- 数据：`/v3/reference/dividends?ticker=<标的>`，默认按除息日倒序。用到的字段是 `ex_dividend_date`、`frequency`（一年几次）、`dividend_type`、`cash_amount`。
- 只在没有今天及以后已宣布的除息时推算（`ex_dividend_date.gte=今天` 为空）。
- 取最近一次 `dividend_type` 为 `CD`（常规现金股息）的记录。`frequency` 是 1、2、4、12 之一时，预计除息日 = 那次除息日加 12/`frequency` 个月，落在休市日就往前取最近的交易日。还在今天之前，就再加一个周期，直到不早于今天。金额照抄那一次的 `cash_amount`，同样标「预计」。
- 不推算、标「除息无数据」的情形：没有任何除息记录；最近一次不是 `CD`；`frequency` 缺、为 0 或不在上面几个值里。这时不发除息提醒，专家被问到时照实说。

## IV 历史（2026-11-17 使用者定）

- **回填一年。**往期权自选里加一只标的时，用期权日线（含已到期合约，查合约要带 `expired=true`）补最近一年，供 IV rank 和百分位用。P1 实测已到期合约的日线至少回溯到 2021-12。
- **存原始输入，不存供应方的 IV。**`iv-snapshots` 每行存：标的、交易日、选中合约的代码、行权价、到期日、合约日线收盘价、正股日线收盘价、报价中间价（只日常有，回填没有）、取数时刻。IV 一律由模块用同一个公式算：BS 反解，利率和股息按 theta `options-math` 的假设，写成命名常量。供应方的 `implied_volatility` 只作对照，不进序列。
- **回填和日常同一口径。**两边用同一种合约选法（沿用 theta `selectAtmContract`，到期期限和行权价的选法写成命名常量，两边共用）、同一个价格字段、同一个剩余时间算法、同一个公式。进序列的价格是合约日线收盘价，因为回填只有日线；中间价反解的 IV 只作对照，不进序列。日线是成交价，可能落在 bid 和 ask 之间任何位置，这个噪声是已知限制。选中的合约那天没有成交（没有那根日线），那天记「无数据」，不拿别的价格补。
- **取数时刻**：收盘后、当天日线定下来之后。具体时刻待 P3 实测定（P1 遗留：收盘后 16:15 至 16:30 的样本还没录）。
- 序列里不同口径的值不能混。以后要改口径（合约选法、价格字段、公式），整段重算，不在旧序列后面接新口径。

## 成交邮件（`fills`）（2026-11-17）

虚构样例和结构说明在 `option-ta-p1/mail-samples/`，照真实成交邮件的结构重新生成，不含原文。

**信怎么进来**（使用者定）：

- 成交回信发到使用者的一个工作邮箱。使用者在那里设规则，把交易台的信「重定向」到宿主读的 Gmail。重定向保留原发件人，`mail` 连接器按发件人过滤就认得出。`brokers` 写交易台的发信地址。地址是私人数据，只存进私密集合 `brokers`，不进仓库。
- 组织邮箱可能禁止重定向到外部。不行就退回「手动转发 + 主题标记」：使用者手动转发、主题加约定的标记，名单写使用者自己的地址，handler 再按标记认信。这个方案不在第一版。
- 连接器交出 HTML 版正文时，优先解析 HTML，纯文本作后备（宿主改动另有 PR，字段名到时候定）。纯文本里交易表一格一行、空格子没了，分不清成交数量和挂单数量，只能按位置推；推不出来的行进 `skipped`，原因 `unparsed`。

**这些信是什么**：不是券商系统自动发的确认单，是交易台的人工回信，里面贴一张「非正式更新」表，信末声明以对账单为准。所以 `fills` 记的数以后要和对账单、1099-B 对账（tax memo 第 13 节）。`source` 记 `broker-email`。

**取哪张表**：

- 一封信可能是整串往来，含多张不同时刻的表。只取最新一张，也就是正文里第一张交易表（HTML 按文档顺序）。交易台的每封回信各自到达，引用里的旧表在它自己那封到的时候已经处理过。这封信本身没有表时，取到的是引用里的旧表，靠下面的 `id` 去重，不会重记。
- 交易表是第一行是 `Account` 的那张，可能套在别的表的格子里。按列名取值，不按列号：表可能多一列（如 `Executed At`）。

**一行算不算成交**，看两个数量列：

| `Exe Qty`（成交数量） | `Open Qty`（挂单数量） | 处理 | `skipped` 原因 |
|---|---|---|---|
| 有 | 空 | 成交，按订单记增量写进 `fills` | |
| 空 | 有 | 挂单，不是成交 | `working-order` |
| 空 | 空 | 没成交，单已失效 | `not-filled` |
| 有 | 有 | 部分成交，照记增量，行标「部分成交」（见下面「订单键和 `id`」） | |

- 股票行（`Position` 空，描述里没有 PUT、CALL）：第一版不记普通股票买卖，跳过，原因 `stock-trade-out-of-scope`。被指派产生的股票不从这张表来。
- 解析写成纯函数，输入是信和已记的 `fills` 行，回 `fills` 和 `skipped`，测试对两样都断言。feed 只把 `fills` 写进集合。`unparsed`、`duplicate-order-key` 要使用者知道，发一条 notice，由领队问使用者；挂单、没成交、股票行、部分成交不打扰。

**订单键和 `id`**（2026-11-17 使用者定：部分成交第一版先记下来）：

成交行只能新增、不能改：feed 交回的行按 `id` 去重（宿主 `INSERT OR IGNORE`），同一个 `id` 只写第一次。所以一笔单分几次成交时，按订单记累计成交的增量。

- **订单键** `order_key` = `<OCC 代码>:<方向>:<成交日>:<账户短码>`，例如 `AAPL260320C00250000:STO:2026-03-05:QRSTalfa`（虚构）。Roll 的两条腿是两个合约，同一合约分到几个账户是几个账户短码，各是各的订单键。
- **`id`** = `<订单键>:cum<cum>`，例如 `AAPL260320C00250000:STO:2026-03-05:QRSTalfa:cum12`。`cum` 是这封信里该订单的累计成交张数（`Exe Qty`）。同一张表在后面的信里被引用、或被转了两次，算出的 `id` 一样，不重记。
- **增量怎么算**。这封信读到该订单的 `cum` 和累计均价 `avg`（`Avg Price`）。从已记的 `fills` 行里取同 `order_key` 的行：张数合计 `prev_qty`，金额合计 `prev_amt` = Σ（张数 × 价格）。
  - `cum > prev_qty`：新记一行，张数 `cum − prev_qty`，价格 `(cum × avg − prev_amt) / (cum − prev_qty)`。
  - `cum ≤ prev_qty`：不记，也不进 `skipped`。这是同一张表在别的信里重复出现，或信件乱序（后到的信带的是更早的表）。
  - 没有已记的行时 `prev_qty`、`prev_amt` 都是 0，新行就是整单：张数 `cum`，价格 `avg`。
- **精度**。价格按字符串解析成整数「万分之一美元」，不经过浮点（`Avg Price` 最多 4 位小数）。`prev_amt` 用已记行的 张数 × 价格（万分之一）整数求和。新行价格 = `(cum × avg − prev_amt) / (cum − prev_qty)`，按万分之一四舍五入（.5 进位；价格为正，不涉及负数取整），存成 4 位小数。因为 `prev_amt` 用的是已记行舍入后的价格，误差不会逐行累积：记完以后同订单各行的 张数 × 价格 合计与 `cum × avg` 相差不超过 0.00005 × 新行张数（按每股价格算，乘合约乘数才是金额）。算出的价格不大于 0 时不记，进 `skipped`，原因 `unparsed`。
- **部分成交的标记**。表里这一行 `Open Qty` 还有值（没全部成交），新行的 `partial_fill` 为 `true`，否则为 `false`。以后的信补齐时照样只记增量；全部成交后旧行不改（不能改），旧行的 `partial_fill` 仍是 `true`。汇总视图（`ledger`）按 `order_key` 合计张数和金额，不靠单行的标记判断订单是否成交完。
- **同一张表里同订单键出现两行**：只取表内第一行，其余行进 `skipped`，原因 `duplicate-order-key`，发 notice 由领队问使用者。这和「只取第一张以 `Account` 开头的表」一样，是只认第一处；引用里的旧表本来就不读。
- **查已记的行**。`fills` feed 的 `reads` 带 `fills`。宿主给 handler 的每个集合最多 500 行，新的在前（`src/modules/feed-runner.ts` 的 `READ_LIMIT`）。订单键的前几次成交如果已经不在最新 500 行里，`prev_qty` 会算少，新行会把已记的部分再记一遍。部分成交一般在几个交易日内补齐，个人账户 500 行够覆盖，第一版接受。超出时怎么办待确认（例如宿主按条件查、或 handler 只看近 N 天的订单）。`cum` 相同的重复信不受影响：`id` 一样，宿主直接忽略。
- **「后面的信带的是累计成交量」是推测，待验证**。样例里没有部分成交。若实际表里 `Exe Qty` 是「本次成交量」（每封信只列新成交的部分），改用另一种算法：每封信的数量直接记一行，张数 = `Exe Qty`，价格 = `Avg Price`，`id` = `<订单键>:<信 id>`，不读已记的行。那时同一张表出现在两封信里会重记，要另想去重办法。见到第一封真实的部分成交信时定。
- 不用 `<信 id>:<序号>` 作 `id`（上面「本次成交量」的情形除外）：同一张表出现在两封信里时信 id 不同，会重记。
- `id` 不进字段。`fills` 另存文字字段 `fill_id`（值同 `id`）和 `order_key`，`record` 和 `ledger` 靠它们认行、合计。
- 手动记的成交，`record` 按同样的写法拼 `fill_id`：整单成交 `cum` 就是张数；只成交了一部分，由领队问清累计成交量再记。缺账户就问。`fills` feed 已有同 `fill_id` 的行（手动记的）不再写；同 `order_key` 的手动行照样计入 `prev_qty`。字段有出入发 notice，由领队问使用者，数以邮件为准，更正用新记录冲销（tax memo 第 14.1 节）。

**字段**（对齐 tax memo 第 14.1 节「成交（Fill）」）：

- 表里有：账户短码、方向（`Side` 加 `Position` 合成 STO、BTO、BTC、STC）、标的、合约描述、成交数量、均价、限价、成交日、交割日，有的表还有 `Executed At`（只到日期）。
- OCC 代码由标的、到期日、PUT 或 CALL、行权价拼出。描述从右往左切（最后一个 PUT 或 CALL、`MM/DD/YYYY`、`@` 行权价），发行人名里可能有空格、连字符、`&`；行权价可能带小数。到期日以描述为准。
- 表里没有订单号、成交时间、佣金和费用。`order_id`、`trade_time`、`commission`、`fees` 留空，标「待确认」，以后用正式确认单或对账单补。
- 金额不在表里，由张数 × 均价 × 合约乘数算。
- 账户：表里是账户短码，先原样记 `account_ref`。映射到匿名 `account_key` 是下一步，映射表放私密集合。

**解码**：按 MIME 每一部分的 `charset` 解码（见到 utf-8 和 windows-1252），传输编码有 base64 和 quoted-printable。表里的日期是 `DD-Mon-YYYY`，合约描述里是 `MM/DD/YYYY`。

## 团队（2026-11-16 定）

领队加五位专家，再加只在会诊时上场的反方。计算归代码，判断归专家：专家不读原始期权链，只读工具算好的紧凑结果。写入（记成交、改意图、维护期权自选）只归领队，领队调 `data/<集合>` 写。

| 成员 | 负责 |
|---|---|
| 领队 | 分档、共同快照、派活、汇总、写入、对使用者输出 |
| 方向与价位 | 正股趋势和关键价位取自 stock-ta 开放工具；未平仓量墙、GEX、最大痛点、期权异常成交自己算 |
| 波动率与事件 | IV、IV/HV、IV rank、偏斜、期限结构、预期波幅、财报和除息 |
| 策略计算 | 行权价、到期日、张数；方案并排比较，含三种 Roll；流动性 |
| 仓位研判 | 已有仓位按意图：买回、Roll、持有、接股 |
| 账本与税务 | 交易链盈亏、税务视图、wash sale 和跨式标记（第一版范围见 tax memo 第 14.3 节）；1099-B 对账以后加 |
| 反方 | 只在会诊时上场，挑领队汇总的错，不出观点 |

**三档分流**：领队自答（一次工具调用或概念解释）；单专家（一个领域内多步解读）；全员会诊（开仓、Roll 这类要使用者决定的结论）。记成交由领队自己做。

**全员会诊**：领队准备共同快照（不写自己的倾向）→ 开新仓派方向、波动率、策略计算，处理已有仓位派仓位研判、波动率、策略计算，并行、互不可见 → 各自交回结论、关键数字、置信度、作废条件 → 领队汇总，分歧原样列出 → 反方看快照、专家回复和汇总，不看领队推理 → 领队最多修订一次，未采纳的反方意见附在最后。只跑一轮。

**输出五段**：结论、依据、分歧、作废条件、「这是分析，不是交易指令」。

**什么时候改**：反方连续 20 次没改变结论也没实质异议 → 只在开仓类会诊上场；单专家档一半以上升级成会诊 → 收紧分档；某位专家常超上下文预算 → 拆细。
