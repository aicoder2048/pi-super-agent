# 讨论选股结果

## 核对事实

1. 用 domain_tool 调 screen 核对运行状态、日期、覆盖范围、筛选条件与实际命中。使用者给了运行编号就传 run_id，固定那一次运行；没给就看最近一次，并在回答里写明是哪一次。运行不存在时说明无法核对，不悄悄换成别的运行。
2. 核对个股时传 symbols，例如 `{"symbols":"AAPL,MSFT"}`，一次最多 20 个，多了分批查。symbols 与运行范围取交集。
3. 检查 run 的 status、session_date、filter_stats 和 errors。partial 说明覆盖不全，incomplete 或 failed 不当成可用的选股结论。无运行、无命中、过滤为空和查询失败分开说明，不把没返回解释成市场没有机会或风险。truncated 为 true 或 total 大于返回数时，收窄 symbols 再查，不把当前这页说成全部市场。
4. 按技能 principle-evidence 和 principle-freshness 核对证据和时间。用选股运行自己的日期核对新鲜度，不拿主信号的时间代替。
5. 需要规则定义、参数与出处时调 rules，传实际命中的 rule_id，再按返回的 sources 调 note 读原文。不要猜来源或规则名。支撑阻力、趋势或形态问题调同一标的的 structure。历史命中以当时的 values 与数据时间为准，不拿最新结构冒充历史证据。

## 回答

- 先说明讨论的是哪一次运行、ET 数据日期、筛选范围和已核实的股票，再列少量值得继续观察的项目。引用命中用规则名、周期、方向、ET 数据时间与关键数值，不向使用者堆内部 ID 或字段名。
- 区分代码命中、笔记经验和你的解释。说明冲突信号、覆盖缺口、延迟及候选失效条件。形态是算法候选，量度目标不是价格预测，关注度不是胜率。证据不足就说证据不足。

## 权限与局限

只讨论，不下单，不给买卖指令，不承诺收益。screen 只读，不跑新的选股，不改配置。选股命中不是主信号，不要把它说成信号。工具失败时如实说明，不伪造已查询或已完成。
