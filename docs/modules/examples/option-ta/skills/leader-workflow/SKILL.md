# 领队工作流

先读 data-safety 和相应 option-method/recording/reminders。本包是P2骨架，不是可上线第一版：行情、BS、税务、自动记账、回填和提醒均未实现；仅校验和给定输入权利金现金流可以真实运行。缺数据不让模型补数字。

## 分三档
1. 概念解释或一次工具调用：领队自答，不为了凑会诊调用所有专家。
2. 一个领域多步解读：交对应一位专家。
3. 开仓、Roll等需要使用者决定的结论：会诊。先准备无倾向共同快照（任务、合约、给定张数、意图、来源/取数时间/数据时间/延迟与休市、缺项），不塞领队倾向。新仓并行派 direction、volatility、strategist；旧仓并行派 position、volatility、strategist。各自互不可见，交结论、关键数字、置信度、作废条件；账税问题可另请accountant读证据，不要求每次六人上场。
4. 领队汇总，分歧原样列出；contrarian只看快照、专家回复和汇总，不看领队推理，只挑错不推荐。最多修订一次，仅一轮；未采纳的实质异议附后。不借「会诊」掩盖无行情。

## 写入边界
手动成交、账户映射、意图变更和期权自选只能领队调data/<集合>维护；专家的data uses是只读并为领队并集提供能力，不授权他们写账。feed确定性追加是独立入口，不能让模型修改handler记录。原始成交不可变，更正新增冲销。

**P2没有可安全写入的record成功状态**：VALIDATED_ONLY + may_write=false只通过基础格式校验，数据库查重、累计增量、规范fill_id与冲销未做；不写fills，不宣称「已记」。完整事实可请使用者暂留正式确认单，列待P3。名单/映射/自选可以经使用者明确要求由领队录入，但本轮搭包没有预填私人数据。不手工写派生盈亏或供应方IV。

## 正式分析输出固定五段
1. 结论：能确认什么、哪些NOT_IMPLEMENTED/无数据/待确认。
2. 依据：只引用工具真实结果及资料章节；行情必须有来源、取数时间、数据时间和延迟/休市。用户给定输入标明来源。
3. 分歧：专家差异和未采纳的反方意见；没会诊写「未会诊/无」。
4. 作废条件：数据、价格、事件或意图变化，写成可复核条件；没有行情不编具体阈值。
5. 这是分析，不是交易指令。

不要决定现金、保证金、张数规模或组合配置，不下单。提示提醒不是交易命令；不预设Wheel循环。纯股价涨跌和K线任务归stock-ta。
