# Module 的定义（简版）

完整说明见 `module-user-guide.md`。字段和目录以代码 `src/modules/manifest.ts` 为准。

## 定义

**一个 module 就是一个文件夹，里面放着某个领域的全部"专业做法"，包括：**

1. **它是谁**（`module.json`）：领域名、中文名、给 Router 看的一句说明、队名。Router 靠这一行决定一个任务归不归这个领域。
2. **什么时候该动手**（`rules.md`）：哪类外部事件值得开任务，开了以后做到哪一步为止。
3. **事件从哪里来**（`feeds/`）：领域自己的数据源，比如行情报价、邮件。它们会产生触发，交给 Router 判断。
4. **事实从哪里来**（`knowledge/`、`data/`）：权威资料和领域数据表。Worker 回答时有据可查，不靠编。
5. **怎么算**（`tools/`）：确定性的计算或查询，比如技术指标、财报日期。结果可复现，不让大模型心算。
6. **怎么做**（`skills/`）：领域的方法和经验，比如查到多细算够、答复写成什么样。Worker 和成员用到时才读全文。
7. **谁来做**（`agents/`）：几位各管一件判断的专门成员。有成员时 Worker 就是领队，可以把活分派出去并行做。
8. **做得对不对**（`evals/`）：考题，用来检验这个领域的答复有没有调用该调用的能力、说出该说的结论。

## 解读

- **module 只给内容，不改机制。** 宿主、Router、Worker、成员的运行方式对所有领域都一样。module 只是把上面这些内容放到各个角色会去读的位置，所以加一个新领域不用改宿主代码。
- **内容分两半，读者不同。** "该不该做、归谁"（`module.json` 的说明、`rules.md`、`feeds/`）是给宿主和 Router 的。"怎么做"（`skills/`、`tools/`、`knowledge/`、`data/`、`agents/`）是给 Worker 和成员的。写错位置，该读的角色就读不到。
- **module 就是 domain。** 文件夹叫 module，任务上记的叫 domain。一个任务最多属于一个领域（ADR-0009），它拿到的技能、工具和成员都来自这一个 module。
- **结构由目录决定，不靠声明。** `module.json` 只写身份。有哪些组件，宿主扫描这几个固定名字的子目录就知道，每个组件自带描述文件。宿主启动时加载一次，校验不过就拒绝启动。
- **权限跟着任务的来源走，不跟着 module 走。** 同一个 module，你在对话里开的任务能用全部工具；由它的 feed 触发的任务只能读自己的文件夹，要跑额外命令得你批准（ADR-0018、ADR-0021）。module 只能把权限收窄，不能放宽。

## 一句话

**module 是可插拔的领域包。它告诉系统这个领域在什么情况下该做事、依据什么事实、用什么方法、由谁来做，以及怎么验证做得对。**
