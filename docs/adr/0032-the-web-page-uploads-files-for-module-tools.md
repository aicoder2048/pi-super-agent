# 网页可以上传文件，模块工具凭上传编号取

2026-11-18 按使用者的要求拟定（「文件入口加一个上传入口」「上传入口只在网页做就可以」），使用者合并即确认。改写 `docs/ocr.md` 和两段提示词里「使用者只能发文字，不能上传文件」那一句；ADR-0029 的 `fetch` 机制照旧，只是多一种取法。

## 问题

option-ta 的券商导出导入（#198）要读使用者手上的 CSV。网页和 Telegram 都只收文字：把整份 CSV 贴进对话，模型还得把它一字不差抄进工具参数，抄错一个数字没人发现；Telegram 一条最多约 4000 字，放不下 JPM 的导出。

## 决定

**只在网页做。** 输入框旁边一个附件按钮，选一个文件上传。Telegram 不做，它照旧只收文字。

**上传和发话分两步。** 页面先 `POST /upload` 把文件交给宿主，宿主存下、回一个上传编号。使用者再发话时，页面在话的末尾加一行 `附件：<文件名>（上传编号 up-<12 位十六进制>，<大小>）`。这一行就是使用者这句话的一部分，对话里看得见，幕僚长转给模块任务时原样带上。`/say`、宿主和内核都不用为附件改。

**存在宿主状态目录。** `<stateDir>/uploads/up-…`，旁边一个同名 `.json` 记文件名、类型、大小和时间。文件不进仓库，不出这台电脑。现在不自动删；要删就删这个目录里的文件。

**上限 10 MB，一次一个文件。** 和邮件附件的上限一样。`/upload` 的鉴权和 `/say` 一样：token、Origin，正文类型是 `application/octet-stream`（跨站表单发不了这种类型），文件名放在查询参数 `name` 里。

**工具用 `fetch: "upload.file"` 取。** 输入 `upload_id`。宿主在工具代码运行前把那个文件复制进这次调用的临时目录，像 `mail.attachment` 一样把 `fetched`（`file`、`filename`、`mimeType`、`contentType`、`size`）加进输入，调用结束就删副本。这种取法不经连接器，所以包里不要求有对应的 feed。哪个模块的工具都能凭编号取：这是一个人自用的宿主，上传的人就是使用者。

**提示词改口。** 幕僚长和 Worker 原来被告诉「使用者只能发文字，不要请他上传」。改成：需要使用者手上的文件时，可以请他在网页上用附件按钮上传；Telegram 传不了文件。读不出 Gmail 附件时，照旧不让他转存再上传，而是照实说读不出来。

## 没有采用的做法

- **上传直接开任务。** 只传文件不说话，幕僚长不知道要拿它做什么。让使用者照常说一句话，附件跟着这句话走。
- **`/say` 正文带 `attachments` 字段，由宿主拼附件那一行。** 要改宿主、内核和 Telegram 的同一条路。页面拼出来的那一行效果一样，伪造也没有意义，因为发话的人就是使用者。
- **CSV 文字照旧贴进对话。** 文件小时能用，但模型抄写的风险去不掉。导入工具的 `csv` 文字输入只留给工具用例。
