# 助手和成员做出来的东西放进成品目录，宿主事后检查、不拦

## 问题

助手和成员把文件写到哪里，今天完全由模型决定。Pi施工队做 joke 扩展时，领队把代码仓库的绝对路径写进了派活任务，成员就把扩展、测试、文档和技能都写进了仓库。使用者要的是：做出来的东西都放进状态目录下的一个成品目录，按类分好；写到别处时让他知道。拦截是沙箱的事，这次不做。

## 决定

**成品目录。** 默认是 `<stateDir>/output/`，`config.json` 的 `outputDir` 可以改，相对路径按状态目录解析，和 `secretsFile` 一样。`outputDir` 不能是状态目录本身或它的上级，否则令牌和 `state.db` 也算成品目录；也不能放在状态目录的 `workers/` 或 `sessions/` 下面。分类只有一份清单，即 `src/host/output.ts` 的 `OUTPUT_KINDS`。给模型的规则和成品目录里的 `README.md` 都由它生成，本文和其他文档不抄它。现在的分类是：应用 `apps/`、分析报告 `docs/analysis/`、其他文档 `docs/reports/`、数据 `data/`、一次性脚本 `scripts/`、图片和渲染件 `media/`、其他 `misc/`。Pi 的扩展、技能、主题和提示模板都放在某个应用里，没有单独的分类。宿主每次启动都建好这些目录，并按清单重写 `README.md`，已有的成品不动。

**应用编号由宿主给。** 应用的目录是 `apps/app-<编号>-<短名>/`，编号至少三位。助手用 `new_app` 工具要目录：宿主先校验短名，再用 `state.db` 的 `apps` 表（AUTOINCREMENT）给编号，然后建目录。编号按顺序给，删了目录、删了记录、重启宿主之后都不会再给同一个编号。同一任务用同一个短名再要，拿回原来的目录，所以重试是安全的。宿主还会看一眼 `apps/` 下已有的最大编号，新编号不会比它小，这样 `state.db` 被换掉时编号也不会和还在的目录撞上。成员拿不到这个工具，目录由领队写进派活任务。推断开的任务只读，没有这个工具，宿主也拒绝它的请求。

**规则写进提示词。** 能写文件的助手（任务不是推断开的）和能写、改文件或执行命令的成员，启动时多追加一段规则：成品目录的绝对路径和分类表。给助手的那一份还要求用 `new_app` 开应用，派活时把绝对目录写进任务，不许让成员写进代码仓库，汇报里写明成品路径。只读的进程不追加这一段。

**汇报时检查，写进汇报。** 每条会到 Router 的汇报都经过检查：带问题的，或者状态不是进展的，也包括宿主替进程写的两种失败汇报（进程中途退出、模型出错）。宿主从上一次检查到的地方往后，读这个任务的助手会话和成员会话。write 和 edit 的路径是确切的。bash 和 bg_start 只记了命令，宿主只能推测它可能写到哪里，结果标成「可能写入」。成品目录、本任务的目录和临时目录算里面。状态目录本身在临时目录里时，状态目录下的其他地方仍然算外面，所以写 `config.json` 照样会被报出来。外面的写入和下一次检查的起点一起存在这条汇报上，同一个事务。Router 收到的卡片末尾多一段「宿主检查（只告知，没有拦下）」，最多列 10 条，多的写还有几处、用 read 读任务看全部；Router 必须用一句话告诉使用者，举出最多三个路径。网页和 TUI 的任务卡片上多一行「写到成品目录之外 N 处」。带外写的「无需处理」汇报也会通知 Router，因为写到外面的事使用者必须知道。宿主不拦，也不回滚。

## 为什么不拦

要拦，就得改每一个写文件的入口，而 bash 改不了；要么就是沙箱。沙箱已经单独立项（docs/security/worker-token-theft-memo.md 的修法 1）。到时候沙箱的写入白名单应该用 `OutputRoot` 里判断里面和外面的同一份规则，不另写一份。

## 没有采用的做法

- 计数文件，模型自己领编号：正确性靠模型，删了文件就会复用编号。
- 开任务时就分好应用目录：不做应用的任务也要用掉编号，一个任务也做不了两个应用。
- 任务结束时另发一张通知卡：同一件事两张卡，和汇报的发送还有竞态。
- 扫文件修改时间：看不出是谁写的，范围也没有边界。

## 代价

- 同一轮里汇报之后才写的文件，这条汇报看不到。任务接着做时，下一条会到 Router 的汇报会补上；任务就此关闭的话就漏掉了。
- bash 只能推测，有误报也有漏报：脚本内部写的文件看不到，`cd` 到仓库之后跑的脚本会被报出来。
- 使用者在对话里明确点名要写到别处时，模型可以照做，这些写入照样出现在「宿主检查」里，宿主分不出是不是使用者点名的。
- 被叫停的任务不补检查。
- 领域的 `prepare` 命令以 shell 运行，不在检查范围内。
- 状态目录搬家之后，旧会话里 `new_app` 返回的绝对路径会失效，和 ADR-0012 一样。
