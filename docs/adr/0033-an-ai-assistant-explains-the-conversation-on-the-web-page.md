# 简报官在对话里就地讲解看不懂的话

2026-11-18 按使用者的要求拟定，使用者合并即确认。想法来自 interactive-courseware 的课件助教。

## 问题

幕僚长和助手的回答里常有使用者不熟的术语（跳空、IV Rank、期限结构倒挂）和知识（IV/HV）。现在只能在对话里再问一句。这样会开新任务、打断原来的任务，回答也不针对那句话。

## 决定

**名字叫简报官。** 使用者 2026-11-18 选的。原型是每天给总统讲《每日简报》的简报官：坐在旁边，讲总统看不懂的地方，回答追问。这里使用者是「总统」，幕僚长和专家交上来的话就是「简报」。按模块分身份时叫「期权研究组简报官」，不属于模块时就叫「简报官」。代码里仍叫 assistant。


**就地批注，不另开窗口。** 回答作为批注展开在被问的那句话下面，和对话一样宽，可以收起。使用者 2026-11-18 用过第一版（右栏一个聊天页）后改的：右栏太窄、离原句远，还和中间栏的对话框重复。泛泛的问题在中间栏问幕僚长；简报官只讲某句话、某个词。

**两种问法。**
- 对话里每句话旁边有「问简报官」，点了就问这一整句。
- 在对话里选中一个词或一小段，浮出「问简报官」，点了就问这几个字。
- 点了立刻就问，问题是固定的一句（「这句话是什么意思？……」或「「某词」是什么意思？在这句话里指什么？」）。
- 想接着问，点批注上的「再问」，在批注里输入；问题还是绑在那句话上。

**专家身份和上下文。**
- 被问的那句话属于哪个任务，简报官就以那个任务所属模块的简报官身份回答。比如 option-ta 是「期权研究组简报官」。
- 模块的标题、说明、团队名和 `knowledge/glossary` 术语表都放进它的背景。
- 不属于模块的话，由「简报官」回答，背景是宿主的术语表 `GLOSSARY.md`。
- 每次提问都带上：选中的字、整句话、这句话前后几句对话。
- 简报官只解释，不读私密集合，不调工具，不联网，不开任务，不写数据。
- 要实时数据或要做事的问题，它会建议使用者在对话里问幕僚长。

**模型。** 走宿主已有的模型订阅（`openai-codex/*`），和幕僚长同一个选择器，不用按量计费的服务。简报官是宿主进程里一个独立的模型会话，接着上下文聊；会话文件存在 `<stateDir>/sessions/assistant/`。

**问答存在宿主。** 问答写进 `state.db`，电脑和手机打开网页看到同一份。每条回答记着它关于哪句话（`about.lineId`）和问的是什么（`question`），页面靠它把批注挂到那句话下面。

**讲法。** 使用者 2026-11-18 定：深入浅出但要简洁。先一句大白话说是什么，再打一个生活里的比方，再只挑原句里最关键的一两个数字说意味着什么；不逐条复述原句，150 字左右。

**语音。** 每条批注有「▶ 朗读 / ⏸ 暂停 / ▶ 继续」，空格键也能暂停和继续（焦点在输入框或按钮上时除外）。宿主用 edge-tts 晓伊（`zh-CN-XiaoyiNeural`）合成。
- 页面只用一个音频元素，点「朗读」时先在上面放一段静音解锁，后面的句子才不会被浏览器的自动播放限制拦住。网页的 CSP 有 `media-src blob: data:`，否则 `/speak` 取回的音频放不出来（第一版就是这样，页面一直退回本机的男声）。
- 回答按句切开，一句一句合成、边合成边播。合成结果按「声音 + 文字」缓存在 `<stateDir>/tts/`。
- 朗读前按读音表换读法，比如 IV Rank 读「I V 排名」。仓库里的通用读音表 `src/host/assistant/pronounce.json` 只放术语；股票代码、券商这类私人的读法写进 `<stateDir>/pronounce.json`，只在本机，盖过通用表的同名词。
- **使用者 2026-11-18 选了晓伊而不是本机朗读，知道朗读的文字（包括张数、金额）会发到微软的服务。**
- 合成失败时，页面退回浏览器自带的朗读。

**先做网页，Telegram 以后再看。**

## 没有采用的做法

- **DeepSeek 按量计费**（课件助教的做法）：使用者选了订阅。
- **浏览器本机朗读做主路**：文字不出设备，但音色取决于设备。使用者要晓伊的音色。
- **右栏聊天页**（第一版）：太窄，离原句远，和中间栏的对话框重复。
- **问答只留在当前页面**：换设备就看不到，以后接 Telegram 也接不上。
- **简报官能调模块工具**：它就不只是解释了，还会碰私密数据和行情配额。要查数据的问题交给幕僚长。
