# lookup 由领域在 module.json 里开

改写 ADR-0005 里「每种依据都有这个工具」一句；ADR-0005 其余内容（宿主运行数据源、凭据只在宿主、参数严格校验）不变。ADR-0008 的「权限只收窄」和 ADR-0009 的「领域就是模块，模块只在启动时加载」都不变。

## 问题

`lookup` 原来对每个助手和每位没在 `tools` 里收窄的成员都开着。使用者要的是：只有 us-market 领域的看盘队能查行情（方案一，团队一级），队里哪位成员能查再单独控制（方案二，成员一级）。代码里不能写死模块名：端到端测试里的领域叫 `watch`，以后别的模块也可能要查数据。

## 决定

**团队一级：module.json 的 `tools`。** 模块写 `"tools": ["lookup"]`，这个领域的助手和成员才有 `lookup`。能由模块开的工具只有一份清单（`src/worker/tools.ts` 的 `DOMAIN_GATED_TOOLS`，现在是 `lookup` 和 `tripwire`，后者见 ADR-0017，只有助手能用）。`tools` 写错（不是列表、空列表、清单外的名字）启动报错，以 module.json 开头。`Modules.kitFor` 是唯一读这个字段的地方：它把领域开的工具交给助手（`DomainKit.granted`），并把成员的 `tools` 按领域收窄，没开 lookup 的领域里，没写 `tools` 的成员拿到除 `lookup` 以外的全部成员工具。没有领域的任务（对话里幕僚长没给领域的、使用者规则开的、模块已被删掉的）一律没有 `lookup`。

**成员一级：成员文件已有的 `tools` 行。** 成员实际的工具仍是「依据允许的」∩「领域开的」∩「成员自己写的」。去掉某位成员的 `lookup`，就从它的 `tools` 删掉这个词再重启宿主。成员写了 `lookup` 而模块没开，启动报错，以成员文件开头，说明在 module.json 开或从成员去掉，不悄悄丢掉。

**宿主是裁决者，注册只管看得见。** 宿主只把 `PSA_LOOKUPS`（可查来源的说明）发给能查的进程，扩展只在拿到它时注册 `lookup`。真正的检查在宿主：`WorkerExecutor.handleRequest` 收到 `worker.lookup` 时，助手按任务领域的 kit，成员按 `DispatchDesk.holder` 认出的那位成员收窄后的 `tools`，不许就拒绝，数据源收不到请求。

us-market 的 module.json 加了 `"tools": ["lookup"]`，看盘队四位成员的文件不变，它们本来就都写了 `lookup`。pi-pi 和 toy-market 不开。

## 为什么检查放在宿主

助手有 `bash`，可以绕过工具，自己往 socket 发请求；请求和规则任务的助手也没有 `tool_call` 拦截。只在扩展里不注册工具，挡不住这样的调用。宿主按令牌认出是谁，再按模块数据判断，所以一个进程用自己的令牌，在 worker 里做什么都查不到领域或成员没开的数据。

这道检查挡不住偷来的令牌。令牌是持有即可用的凭证，放在 worker 启动时的环境变量里，同一用户下 `ps eww` 看得到兄弟进程的初始环境。成员可以拿自己助手的令牌按助手的权限查，没有领域的助手可以拿别的任务的令牌查。这个缺口在本决定之前就有（同样的令牌也能汇报和读任务），要靠换掉令牌交给 worker 的方式来补，是以后单独的决定。

## 没有采用的做法

- **只加一个开关变量、按它注册工具**：只是看不见，不是不能用，还多一个要和 `PSA_LOOKUPS` 保持一致的变量。
- **按 `PSA_CREW` 判断成员、名单可热加载**：`PSA_CREW` 是助手能派活的名单，成员拿不到它；判断放在不可信的进程里；热加载等于 module.json 之外再有一份配置。
- **在 module.json 里另列能查数据的成员**：每位成员的工具会写在两个文件里，改一个看不到另一个，迟早对不上。成员的 `tools` 本来就是逐位的清单，宿主也读它。
- **有 `feed` 的模块自动能查**：把「能查」和「拥有数据源」绑在一起。以后要查行情的组合模块就得自带数据源，而 toy-market 有 `market: true` 却没有数据源，说明这两件事本来就不同。

## 代价

- 没有领域的助手查不了数据。使用者规则作用在 us-market 来源上时，开的行情助手没有领域，也就没有 `lookup`。要它能查，把规则放进 `modules/us-market/rules.md`（模块规则的任务属于这个模块），或让幕僚长选 us-market 领域。
- 改谁能查要重启宿主，和改模块的其他地方一样。
- 开了 lookup 的领域能查宿主登记的所有数据源，不限于自己的。按来源收窄是以后单独的决定。
