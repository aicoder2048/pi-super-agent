# 提醒响不响由模块决定

2026-11-13 按使用者的决定拟定（`docs/modules/stock-ta-rules-design.md` 第 1、6、10 节，PR1 的宿主改动 H1）。修改 ADR-0017「提醒发到所有前端……带通知」的说法。ADR-0017 的其余部分不变：提醒仍是一行、去重、不经幕僚长，种类仍然决定一行是不是提醒、能不能出本机。

## 问题

stock-ta 要像交易员一样盯盘：规则多了，提醒就多，每一行都让手机响就成了噪音。使用者定下的事件层级里有「静音提醒」一层：网页和 Telegram 各一行，Telegram 不响。个股当天涨跌到 5%、SPY 和 QQQ 到 2% 的那一行就是这一层，8% 和 3% 才响。

今天做不到。Telegram 客户端发宿主行时写死了带通知（`silent: false`），`bot-api.ts` 支持 `disable_notification`，但模块没有办法要求它。

## 决定

**提醒可以静音。** 模块 feed 交回的提醒多一个可选的 `push`，现在只有一个值 `"silent"`。不写就和今天一样响铃。宿主把它带到底：

- `FeedAlert` 和 `Alert` 带 `push`，`parseCollected` 只认 `"silent"`，别的值这一轮失败并说出原因。
- 宿主行 `HostLinePost` 和 `HostLine` 带 `push`，存进 `host_lines` 的新列 `push`。库表的 CHECK 只许提醒静音，只许 `'silent'`。旧库打开时补上这一列，旧的提醒读回来照旧响铃。
- Telegram 客户端发静音的提醒时带 `disable_notification`。重启后补发没送达的提醒时，从库里读回 `push`，照样静音。
- 网页照常显示这一行，只是不弹出「今天」面板。

**响不响由模块决定，种类仍然决定去向。** 模块最清楚一行有多急。宿主不认识 stock-ta，也不认识层级，只照提醒上写的做。提醒和收据、通知的分别、哪些能出本机，仍由种类决定（ADR-0017、ADR-0016）。

**和你设的条件并成一行时照条件的响。** 你设的当天涨跌条件和 feed 的提醒同一轮、同一方向到线时并成一行（ADR-0017 的检测部分之后加的做法），这一行是条件的提醒，照旧响铃。条件是你亲口要盯的线，不跟着模块静音。

## 没有采用的做法

- **在 Telegram 客户端里按文字或来源判断要不要静音。** 宿主就得认识模块和它的规则。模块说一句 `push` 更直接，代码里也只有一个地方要看。
- **一开始就做 `push: "badge"`（只做页面标记，不发 Telegram）。** 设计里有，是第 5 期的 H3。它要动网页的模块卡片，这一期用不上。第 5 期做了，但没有在宿主行的 `push` 上加值：标记不是一行，存在自己的表里，见 ADR-0028。宿主行的 `push` 仍然只有 `silent`。
- **让每条宿主行都能静音，包括通知。** 通知是 `just notify` 和来源出错的话，使用者要求一定看到。CHECK 只许提醒静音。

## 代价

- Telegram 的静音只是不响铃、不震动，通知栏里照样有这一条；使用者在系统里把机器人设成免打扰时，响铃的提醒也不响。
- 静音的一行容易被忽略。所以只给使用者定下可以静音的层级用，例如到档的第一档；会开任务的第一档，汇报到的时候照常响铃。
