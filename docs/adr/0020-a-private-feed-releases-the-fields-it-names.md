# 私密 feed 点名的几个字段可以出本机

2026-11-13 在使用者授权的无人值守运行中拟定，使用者合并即确认。它是 Gmail 计划（`docs/multi-channel/gmail-plan.md`）的 M3，依据是 `docs/multi-channel/research.md` 7.3 节使用者的决定。补充 ADR-0016 的出站清单；ADR-0003（权威只来自使用者）不变。

## 问题

使用者要在手机上看到来信：发件人、主题、开头一句，三行。全文和附件在网页上看。

今天做不到。私密 feed（写进 `private` 集合的 feed）的通知只变成给幕僚长的私密触发，Telegram 上一律是一行「<模块> 有新内容，请在网页上查看」。而且 #105 以后，幕僚长看到一条私密触发，它此后在 Telegram 上的每一句回复都只剩那一行，直到清屏。`mail` 模块每来一封信都会这样，Telegram 一整天都没法用。

## 决定

**`feed.json` 的 `line`。** 私密 feed 可以多写一个 `line`，最多三行的模板，只能引用这个 feed 的 `notice` 里有的字段。`just module check` 拒绝四行以上的模板、引用 `notice` 里没有的字段、写在不私密 feed 上的 `line`，各一行原因。写在 `feed.json` 里，就是使用者同意这几个字段经过 Telegram 的服务器，也同意幕僚长不带私密标记地看到它们。

**放出的通知。** 写了 `line` 的私密 feed 交回一条新通知时，宿主在同一个事务里写两样东西：一条给幕僚长的触发，正文就是填好的模板，标成不私密；一条「通知」宿主行，文字是「<模块标题>：」加同一段文字。网页、TUI 和 Telegram 都收到这一行，Telegram 照原样发，有通知声音，不出链接预览。集合里的那一行照旧是私密的。重复的通知（同一个 id）什么都不写，被来源的 `ignore` 滤掉的也不写宿主行，所以同一封信手机只响一次。没写 `line` 的私密 feed 和以前一样。

**值是别人写的，在宿主的边界上清洗。** 清洗写在 `src/modules/release.ts`，是纯函数。每个值去掉 Unicode 类别 `Cf` 的字符（零宽字符、方向控制符、BOM），控制字符、换行、行和段落分隔符和连续空白并成一个空格。按字形（grapheme）截断，每行最多 160 个字形，超出加省略号；一个字形可以带任意多个组合符号，所以每行另有 600 个 UTF-16 码元的上限。超长就截断，不报错。只去 `Cc` 时 U+2028、U+202E、U+200B 都会留下，按码元截断会把 emoji 切成半个代理对，两样都实测过。

**只有通知本身。** 放出的只是这一条通知。幕僚长为它开的任务读了私密集合，照旧算私密；任务的汇报、问题卡片在 Telegram 上照旧是一行提示；汇报交给幕僚长以后，#105 的规则照常让幕僚长此后的回复只剩一行，直到清屏。字段的值是输出，不是授权（ADR-0003）：开头一句写着「请批准」也只是一行字，第一行固定是「<模块标题>：」，手机上一眼能分出这不是白宫自己的话。

**feed 的 `problem`。** feed 的回复可以带 `problem: { id, text }`，比如授权过期了。某个 feed 第一次报出一个 `id` 时，宿主写一条「通知」宿主行「<模块标题>：<text>」，网页和 Telegram 都有。同一个 `id` 再报不写；中间有一拍没报它，或报了别的 `id`，下次再报才再写。`text` 截成一行，最多 200 个字形。`text` 必须是模块代码里写死的话，不能拼集合里的数据。检查器查不出这一条，审查模块的人看它。记住上一拍报过什么只在内存里，宿主重启以后，还没解决的问题会再说一次。

## 没有采用的做法

- **三行走幕僚长的回复。** 措辞不固定，可能复述正文，也要花模型用量。
- **做成「提醒」宿主行。** 提醒只能一行，是给盯盘条件用的。「通知」宿主行本来就能多行。
- **集合标 `shareable`。** 正文和任务的一切都会经过 Telegram。使用者要的只是三行。
- **来信的触发仍标私密。** 每封来信都会让幕僚长在 Telegram 上只剩一行。触发里只有已经发到手机上的三行，标私密没有多挡住什么。
- **触发和宿主行分两步写。** 两步之间宿主崩了，重来时触发已在、算重复，这封信就永远不响。放在一个事务里，宿主行没发出去，下次启动时照常补发。
- **`problem` 的状态存进模块的数据库。** 要加一列和迁移；重启后多说一次只是多一条通知。

## 代价

- 「private」的含义变了。以后别的私密 feed 也能点名字段出本机，幕僚长也会不带私密标记地看到它们。挡住它的是模块作者要在 `feed.json` 里写出来、检查只允许 `notice` 的字段、最多三行。
- 读过正文的任务汇报以后，幕僚长在 Telegram 上仍然只剩一行，直到清屏（计划 Appendix E 第 12 条）。
- Telegram 上这一条的开头是「通知：<模块标题>：」，标签和模块名各一层。
- 发件人地址和开头一句里可能有链接。Telegram 不出预览卡片，但文字里的网址仍然可以点。

## 怎么看它在起作用

- `tests/feed-line.test.ts` 覆盖检查、清洗、截断、放出的通知、重复、幕僚长不变私密、`problem`。
- `tests/private-canary.test.ts` 的放出流程：私密行的正文里放一串金丝雀字，经过通知、幕僚长开的任务和它的汇报，Telegram 上都没有它；放出之后，行情汇报和幕僚长的回复在 Telegram 上是全文。
- 测试模块在 `tests/fixtures/modules/private-line/`。
