# 点选项就是使用者自己说的话

助手提问时可以给 2 到 4 个选项。使用者在网页上点一个按钮，或在终端回一个序号，宿主把它写成「回答任务「标题」：选项」，作为使用者在对话里的一句话交给幕僚长，和打字一样经 Router 转交给任务（ADR-0003）。程序不绕过 Router 直接写给任务；这条话只能转交给提问的那个任务，开新任务或转交给别的任务都会被拒绝。

点了哪一项记在 `answer_clicks` 表里（触发 id、汇报 id、选项序号），不从那句话反推。一次点击对应一条触发，去重键是 `answer:<汇报 id>:<第几次>`。连点同一项、网页和终端各点一次、超时后重试，得到的都是同一条触发，再点仍然返回成功；换另一项再点被拒，回「已选「X」」。

点选只有转交给提问的任务才算回答。看板上的问题带着最近一次点选和它的进度：幕僚长还没处理完是「已发送，等待幕僚长转交」；转交了是「已回答」，问题留在看板上直到任务下一次汇报；幕僚长忽略了它，或这一轮结束了也没有转交，这次点选作废，按钮重新可点，再点是一条新的触发。「还没处理完」按通知幕僚长的那条动作是否还挂着来判断：那条动作要等看过这张卡片的一轮正常结束才算完成。

提问之后使用者又打了一句话，而幕僚长还没处理完那句话时，点选被拒，网页和终端把按钮锁住，免得打的字和点的选项都送到任务手里、互相矛盾。幕僚长把那句话转交给这个任务，问题就结束了；交给别处或只是回了一句，按钮重新可点。先点选、再打字的顺序不拦：两句按先后到达任务，Worker 以使用者后说的话为准。

推断任务读过外部内容，它的选项可能被注入，例如「同意发送全部草稿」。我们接受这一风险：推断任务本身不能做对外动作，只能产出草稿；按钮上的文字原样出现在那句话里，使用者看过之后自己选，点击才算授权。
