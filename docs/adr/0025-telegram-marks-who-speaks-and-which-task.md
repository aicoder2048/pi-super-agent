# Telegram 上标出谁在说、说的是哪个任务，回复按 Markdown 显示

2026-11-13 按使用者的决定拟定。取代 ADR-0016「没有采用的做法」里「MarkdownV2 格式……发纯文本」那一条。只改 Telegram 客户端（`src/host/telegram/`），网页、终端、Router 和 Worker 的提示词不动。

## 问题

使用者在手机上看到的三件事：

1. 幕僚长的话、系统的话（「你在网页或终端说：…」）、通知（邮件、到价提醒、来源出错）、助手的问题卡片长得一样。机器人私聊里所有消息只有一个头像，气泡也不能换颜色。
2. 几件事同时在跑时，回答交错着到，分不清哪句回答对应哪句问话。
3. 幕僚长的长回复是 Markdown，到了手机上星号、井号、竖线原样露着。

## 决定

**每条消息开头标出谁在说。** 🧭 是幕僚长（名字加粗），⚙️ 是系统，🔔 是通知，🙋 是助手（或命令卡片上的「白宫 · 系统」）的问题卡片。

**每个任务一种颜色的圆点。** 八种颜色（🟢🟣🔵🟠🟡🔴🟤⚪）按任务第一次有消息到 Telegram 的先后轮换，同一个任务的每条消息都带同一个圆点，跟着任务一直不变。和任务无关的消息没有圆点。

**挂在开任务的那句话下。** 任务的回复和卡片用 Telegram 自己的回复（`reply_parameters`），挂在使用者开这个任务的那条消息下面；那句话是在网页或终端说的，就挂在转到手机上的「你在网页或终端说：…」下面。带 `allow_sending_without_reply`，那条消息被删了也照发。卡片的编辑不能改挂靠，只改文字。

**幕僚长的回复按 Markdown 显示。** 转成 Telegram 的 HTML（`parse_mode: HTML`）：粗体、斜体、删除线、行内代码、代码块、链接（只认 http 和 https）、引用；标题变一行粗体，列表用「•」，表格一行一行写，格子之间用「 | 」。别的文字（通知、卡片、说明）照原样显示，只做 HTML 转义。

**长回复折叠。** 前 5 行直接显示，其余收进可展开的引用（`<blockquote expandable>`）。

**格式不能让消息丢掉。** Telegram 因为 HTML 拒收（400 `can't parse entities`）时，同一条改发纯文本。转换后照旧守 4000 字的上限：按块从后往前去掉，结尾写「…（全文见网页）」，不会切在标签或实体中间；一块本身就超长时整条退成截断的纯文本。卡片的编辑和第一次发出用同一套规则。

## 数据放在哪

`telegram_tasks` 表（`src/host/telegram/store.ts`）：`ticket_id` 主键、`dot`（颜色序号）、`origin_line_id`（开任务的那句话的对话行 id，来自内核任务的 `origin_trigger_id`）。任务第一次有消息进发件箱时写一行，之后不改，所以宿主重启颜色和挂靠都不变。开任务那句话在手机上的 `message_id` 不另存：发件箱 `telegram_messages` 里 `line:<行 id>` 那一行本来就记着，取下一条待发消息时一起查出来。换了机器人时和别的 Telegram 表一起清掉。

## 没有采用的做法

- **每个任务一个话题（forum topic）。** 私聊里没有话题；ADR-0016 也不做。
- **MarkdownV2。** 转义规则比 HTML 严得多，出错率高；HTML 只要转义三个字符。
- **把幕僚长的长回复拆成几条。** 一条对话行仍是一条消息，和以前一样。
- **按当前在跑的任务挑没用过的颜色。** 八种颜色轮一圈之前同时在跑的任务不会撞色，够用。

## 代价

- 消息开头多了两三个字符；一屏能看的字略少。
- 幕僚长的回复里如果真想写星号或下划线，可能被当成强调。`snake_case` 这类词不受影响。
- 能改的旧卡片在升级后第一次变化时会带上新的标记和圆点；升级前就发出、之后不再变的消息保持原样。
