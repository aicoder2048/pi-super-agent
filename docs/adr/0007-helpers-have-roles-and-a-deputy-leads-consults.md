# 助手有角色：每个任务由副幕僚长牵头，副幕僚长按专家名册请教

到 W5 为止，所有助手都是同一个：同一份系统提示词，工具只按任务依据分两档，技能只在规则任务里来自模块。幕僚长的 `route` 只决定做不做、做什么，不决定谁来做；它也不拆任务、不汇总多个助手的结果。根子在于模块只提供输入（来源、规则）和一点知识（skills），不提供执行者；`route` 里也没有「谁」这个词。

## 拓扑

```
默认：    使用者 <-> 幕僚长 <-> 副幕僚长 <-> {通用助手, ...}
看盘模块：使用者 <-> 幕僚长 <-> 副幕僚长 <-> {行情分析师, 技术分析师, 新闻研究员, 财报解读}
```

幕僚长只派牵头角色；每个任务都由一位牵头角色负责，起步只有内置的副幕僚长。专家从不负责任务，只回答牵头角色的问题。技术分析（K 线、均线、成交量形态）和行情分析（涨跌、异动、板块）是两个专家，分开定义。

## 角色

角色是一份 Markdown 定义，格式沿用 `.pi/agents/*.md`：frontmatter 写 `name`（英文 id）、`title`（中文职称）、`description`（擅长什么）、`tools`（工具白名单）、`skills`（技能目录，可多个）、`model`（可选）、`consult`（是否牵头，默认否），正文是这个角色的系统提示词。`consult: true` 的是牵头角色，其余是专家。

角色来自三处，同名在启动时报错，不互相覆盖：

- 内置：`deputy`（副幕僚长，牵头）和 `general`（通用助手，默认专家，就是 W5 及以前的助手）。
- 模块：`modules/<模块>/roles/*.md`。装了看盘模块，专家名册里就有它带来的专家。
- 使用者：`<状态目录>/roles/*.md`。

没有任何模块角色时，副幕僚长只能请教通用助手，或者自己做。

角色是长期存在的身份；W5 的「知微」是某个任务里的一次实例。页面上合写成「知微 · 副幕僚长 #3」，#N 按角色在纽约同一天里数。W5 按来源起的名字（对话助手、行情助手等）不再出现，来源已经写在依据那一行。

## 幕僚长只派牵头角色

幕僚长的提示词里只有牵头角色的名册：`name`、`title`、`description`。`route` 的 `open_ticket` 多一个可选参数 `role`，省略就是副幕僚长；只能填牵头角色，填专家或不存在的名字，内核拒绝这个决定并说明。这个参数留给以后模块声明的牵头角色（例如行情主管）。

角色写进任务记录（`tickets.role`），重启不变。旧任务没有角色，归副幕僚长。

## 副幕僚长按专家名册请教

牵头角色的提示词后面接一份专家名册：每位专家的 `name`、`title`、`description`。简单的事副幕僚长自己用本任务依据允许的工具做，例如查一次股价用 `lookup`，不请教谁。

规则可以在 `rules.md` 里写一行 `专家：<name>[, <name>]`，提示副幕僚长该请教谁。启动时校验这些名字都在专家名册里；按这条规则开任务时，内核把这行提示接在任务说明末尾。它只是提示，不指定任务归谁。

## 权限只收窄不放宽

Worker 的工具 = 任务依据允许的工具 ∩ 角色的 `tools` ∪ 汇报类工具（`report`、`hand_back`、`read_ticket`）。推断任务即使派给写了 `bash` 的角色，也仍然只读（ADR-0003）。角色的 `model` 也要过计费检查，`anthropic/*`、`deepseek/*` 和 Claude 模型被拒。

## 会诊（W6b）

牵头角色多一个 `consult` 工具：一次提交一到四个问题，每个问题指定专家名册里的一位，所有问题同时开始，结果一起返回。每次会诊起一个短命的 Pi 子进程，用被问专家的提示词，一问一答，答完就结束，不建任务、不订阅线程。

- 只有一层：专家没有 `consult`，牵头角色不能会诊另一个牵头角色。
- 被问的专家只读：`read`、`grep`、`find`、`ls`、`web_get`、`lookup`，再与它自己的 `tools` 取交集。会诊是为了回答问题，不做事；要做事，由牵头人在自己的任务里做，仍受任务依据约束。
- 会诊的 token 计入这个任务和当天用量，回退模型的每日上限照样生效。每个问题有时限，超时的专家记为没有回答，其余照常返回。
- 页面上，执行过程里展开每次会诊：问了谁、问了什么、谁答了什么、用了多少 token。页头助手条在牵头人下面列出正在回答的专家。被问的专家只活一次回答，只写角色名，不起个人名字。

## 没有采用的做法

- 幕僚长按名册直接派专家（ADR 初稿的拓扑甲）：一件事横跨几个领域时，幕僚长要么只派一个领域，要么自己拆和汇总，违背它快速分派、不阻塞的设计。使用者 2026-11-09 选定拓扑乙。
- 规则用 `角色：` 指定任务归哪个专家：任务一律归牵头角色，规则只提示该请教谁。
- 幕僚长自己拆和汇总（父任务带子任务，全部汇报后合成）：幕僚长要等、要合成。
- 被问的专家建成长期任务：一问一答的研究不需要订阅、恢复和停止，建任务只会让看板变乱、开销变大。
- 不同牵头人互相会诊：层数和费用都难以控制。
