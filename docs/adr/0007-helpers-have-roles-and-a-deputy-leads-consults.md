# 助手有角色：模块提供角色，幕僚长按名册派人，副幕僚长牵头会诊

到 W5 为止，所有助手都是同一个：同一份系统提示词，工具只按任务依据分两档，技能只在规则任务里来自模块。幕僚长的 `route` 只决定做不做、做什么，不决定谁来做；它也不拆任务、不汇总多个助手的结果。根子在于模块只提供输入（来源、规则）和一点知识（skills），不提供执行者；`route` 里也没有「谁」这个词。

## 角色

角色是一份 Markdown 定义，格式沿用 `.pi/agents/*.md`：frontmatter 写 `name`（英文 id）、`title`（中文职称）、`description`（擅长什么，给幕僚长看）、`tools`（工具白名单）、`skills`（技能目录，可多个）、`model`（可选）、`consult`（是否牵头会诊，默认否），正文是这个角色的系统提示词。

角色来自三处，同名在启动时报错，不互相覆盖：

- 内置：`通用助手`（没有 frontmatter 限制，就是 W5 及以前的助手）和 `副幕僚长`（`consult: true`）。
- 模块：`modules/<模块>/roles/*.md`。装了行情模块，名册里就有行情模块带来的角色。
- 使用者：`<状态目录>/roles/*.md`。

没有任何模块角色时，行为和现在一样：幕僚长只能派通用助手或副幕僚长。

角色是长期存在的身份；W5 的「边牧」是某个任务里的一次实例。页面上合写成「边牧 · 行情分析师 #2」；通用助手沿用 W5 按来源起的名字（对话助手、行情助手、规则助手、观察助手）。

## 幕僚长按名册派人

幕僚长的提示词里有一份名册：每个角色的 `name`、`title`、`description`。`route` 的 `open_ticket` 多一个可选参数 `role`，省略就是通用助手。规则可以在 `rules.md` 里写一行 `角色：<name>` 指定角色；幕僚长按这条规则开任务时必须用它，内核校验，不符就拒绝这个决定。

一件事只涉及一个领域，派那个领域的角色；需要拆开问几个领域、再合成一份答复，派副幕僚长。幕僚长自己不拆、不汇总，它仍然只做快速的分派，不等任何助手。

角色写进任务记录（`tickets.role`），重启不变。旧任务没有角色，按通用助手处理。

## 权限只收窄不放宽

Worker 的工具 = 任务依据允许的工具 ∩ 角色的 `tools` ∪ 汇报类工具（`report`、`hand_back`、`read_ticket`）。推断任务即使派给写了 `bash` 的角色，也仍然只读（ADR-0003）。角色的 `model` 也要过计费检查，`anthropic/*` 和 `deepseek/*` 被拒。

## 副幕僚长牵头会诊

`consult: true` 的角色多一个 `consult` 工具：一次提交一到四个问题，每个问题指定名册里的一个角色，所有问题同时开始，结果一起返回。每次会诊起一个短命的 Pi 子进程，用被问角色的提示词，一问一答，答完就结束，不建任务、不订阅线程。

- 只有一层：被问的专家没有 `consult`，牵头角色不能会诊另一个牵头角色。
- 被问的专家只读：`read`、`grep`、`find`、`ls`、`web_get`、`lookup`，再与它自己的 `tools` 取交集。会诊是为了回答问题，不做事；要做事，由牵头人在自己的任务里做，仍受任务依据约束。
- 会诊的 token 计入这个任务和当天用量，回退模型的每日上限照样生效。每个问题有时限，超时的专家记为没有回答，其余照常返回。
- 页面上，执行过程里展开每次会诊：问了谁、问了什么、谁答了什么、用了多少 token。页头助手条在牵头人下面列出正在回答的专家。被问的专家只活一次回答，只写角色名，不起个人名字。

## 先一个副幕僚长，留多个牵头人的口子

起步只有内置的副幕僚长是牵头角色：拆解和汇总的写法只有一处，幕僚长的选择也简单。模块以后可以声明自己的牵头角色（`consult: true`，例如行情主管），幕僚长按 `description` 在几位牵头人之间选；一层会诊的限制不变。

## 没有采用的做法

- 幕僚长自己拆和汇总（父任务带子任务，全部汇报后合成）：幕僚长要等、要合成，违背它快速分派、不阻塞的设计。多个长期任务真正需要协作时再考虑。
- 被问的专家建成长期任务：一问一答的研究不需要订阅、恢复和停止，建任务只会让看板变乱、开销变大。
- 不同牵头人互相会诊：层数和费用都难以控制。
