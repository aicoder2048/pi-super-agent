# 来源可以不经幕僚长，直接对使用者说一行

2026-11-11 在使用者授权的无人值守运行中拟定，使用者合并即确认。补充 ADR-0016 里「哪些内容会离开本机」的清单。ADR-0003（权威只来自使用者）不变：这里说的行是输出，不是输入，不授权任何事。

本文分两部分。出站部分随「宿主行」管道一起落地。写入部分（使用者在对话里改盯盘条件，宿主怎么裁决）随写入口一起补上，见文末的占位一节。

## 问题

使用者要在网页聊天里设盯盘条件（某只股票涨跌多少、偏离成本价多少、均线金叉死叉），条件触发后手机要响，网页上也要有。今天来源（source）的话只有一条路到使用者：来源写触发（trigger），幕僚长看到后开任务，助手查完汇报，幕僚长再回复。这条路经过两个模型，措辞不固定，回复受 200 字限制，每条都花 token；而且幕僚长的回复会发到 Telegram，成本价有没有被复述，只能靠提示词。ADR-0016 的出站清单里也没有「提醒」。

## 决定

**宿主行。** 来源可以经宿主直接说一行给使用者，叫宿主行（host line）。它是来源对使用者说的话，不是触发：不进触发账本，不叫醒幕僚长，不开任务，不算今天的触发计数，也不会被订阅了线程的任务截走。宿主行存在 `state.db` 的 `host_lines` 表里，和使用者、幕僚长的话按时间排在同一个对话里；重载页面后还在，清屏一起收走。宿主行不能引用：引用只对使用者和幕僚长的话成立（ADR-0011），引用一条宿主行和引用不认识的行一样被拒。

**两种宿主行，去向只由种类决定。**

- **提醒（alert）**：一行，1 到 1000 字，不能换行，必须带来源给的 `externalId`。同一来源同一个 `externalId` 只存一次：重复的提醒什么都不写、不再发，和触发的去重一样（ADR-0005）。来源可以问宿主某个 `externalId` 是否已经提醒过。提醒发到所有前端：网页、终端、Telegram。
- **收据（receipt）**：可以多行，最多 16000 字，不去重。它回显使用者存下的盯盘条件，可能写着成本价和股数，所以只在网页和终端出现。

库表的 CHECK 约束守住这些格式。格式不对的行写库时直接报错，来源会知道，不会悄悄消失；只有真的重复才算重复。

**ADR-0016 补充：提醒可以出本机，收据不可以。** 写了 `telegram` 段，就是使用者同意提醒经过 Telegram 的服务器。Telegram 客户端把提醒发到每个名单上的私聊，前面写「盯盘提醒：」，带通知；对它滑动回复是普通的一句话，不带引用。收据在 Telegram 客户端里是显式的「不发」。客户端对广播类型做穷举，以后加了新的广播类型却忘了在 Telegram 里处理，日志会记一行，不会悄悄丢掉。

**送到一次。** 宿主先写库，再广播，再把提醒标记为已送达。宿主在写库之后、标记之前停了，下次启动时在 Telegram 客户端开始收发之前把没标记的提醒再广播一次。Telegram 的发件箱按提醒的编号去重，已经发过的不再发，所以补发不会让手机响两次。网页和终端靠对话快照补上。

**只有提醒受类型保护。** 提醒的文字只由不带成本价和股数的触发结果生成（行情的检测接上之后由类型保证），所以 Telegram 上的提醒没有成本价和股数，只有价格和百分比。成本类提醒写精确的偏离百分比，可以反推出成本价，这是使用者的决定。任务标题和幕僚长的回复不受这层保护：它们由模型写，可能复述成本价，再经 Telegram 发出。使用者在网页上说的原话也照旧转到 Telegram（ADR-0016）。这几处使用者已经接受，行情领域的技能里会要求汇报时不复述成本价和股数，那只是软约束。

## 没有采用的做法

- **提醒当触发，加一种新的来源策略和一种「发到频道」的动作。** 重试和耐久现成，但触发和动作的种类已经写进使用者旧库的 CHECK 约束，SQLite 改 CHECK 要重建表；提醒是输出，放进输入账本，今天的计数和线程订阅都要特判；订阅了当天线程的任务会把它截走。
- **让幕僚长转述。** 几乎不用新管道，但措辞不固定，受 200 字限制，每条都花 token，成本价是否被复述只能靠提示词。
- **收据也发到 Telegram，再靠提示词或过滤去掉成本价。** 去向由种类决定，比逐行过滤可靠，代码里也只有一个地方要看。

## 代价

- 提醒和收据不能引用。要引用就得放宽 `trigger_quotes` 的 CHECK，以后单独决定。
- 宿主在把提醒交给 Telegram 发件箱之后、标记送达之前被杀掉，重启后会再交一次；发件箱按编号去重，手机上仍只有一条。Telegram 换了机器人时发件箱被清空，这时补发的提醒会到新机器人那里。
- 宿主行不经过幕僚长，所以幕僚长不知道发过哪些提醒。使用者问「刚才那条提醒是怎么回事」时，幕僚长要去查，或由以后的设计把提醒告诉它。
