# 断了要看得见：警报

模型或数据断了，宿主自己记下来，在网页顶上和 Telegram 上告诉你，修好后再告诉你一次。说这件事的是宿主的代码，不是幕僚长：模型断了的时候幕僚长说不了话。

## 你会看到什么

- **网页。** 页头下面一条红色横幅，每处断了的地方一段：断的是什么（幕僚长模型、助手模型、某个模块的来源），从多久前开始、连着几次、最近一次的错误、怎么办。修好之前一直在。全部恢复后横幅变成绿色的「都恢复了」，列出一小时内恢复的，再过一小时消失。
- **模型和数据同时因为联网错误断了。** 横幅加一句「本机可能断网了」。这是猜的，不是测出来的。
- **Telegram。** 一处断了发一条 `🔔 ⚠️ <什么>出问题了（几点起，几次）：<错误>。<怎么办>`，响铃；恢复时发一条 `🔔 ✅ <什么>恢复了（断了约 N 分钟）`（不到一分钟写「不到 1 分钟」），不响铃。开头的 🔔 和其他通知一样（ADR-0025 的标记）：说话的是宿主，不是幕僚长。同一次断开只发这两条，中间再失败多少次都不再发。只发给在 Telegram 上和宿主说过话的聊天。

## 宿主自己停了

宿主进程崩了、卡住不写心跳、或者一直起不来时，宿主自己说不了话。这时由看门狗说：它是另一个进程，本来就在每 `watchdog.intervalMinutes` 分钟（默认 3）检查一次心跳、没有心跳就重启宿主。

- **宿主停了。** 看门狗见过宿主在跑，这次检查没有心跳（进程没了，或心跳超过 `watchdog.staleSeconds` 没更新），发一条 `🔔 ⚠️ 宿主停了（最后一次心跳 N 分钟前），看门狗正在重启`，响铃。
- **宿主一直起不来。** 看门狗启动后还没见过宿主在跑，连着 3 次重启、每次等完宽限期都没有心跳，发一条 `🔔 ⚠️ 宿主连续 3 次启动失败：<host.log 里最后一行错误>。看门狗会接着重试，详情见状态目录里的 host.log`，响铃。错误照「错误文字」一节去掉密钥。
- **宿主回来了。** 发过 ⚠️ 的那次停机，看门狗再看到心跳时发一条 `🔔 ✅ 宿主恢复了，停了约 N 分钟`，不响铃。停到哪一刻算到看门狗最后一次重启它的时候。
- **一次停机只发这两条。** 中间重启失败多少次都不再发。看门狗自己重启了也一样：停机记在状态目录的 `outage.json`，新的看门狗读到还没结束的停机，就不再发 ⚠️，宿主回来时照样发 ✅。
- **config.json 读不了。** 看门狗启动时读不了 `config.json`（不是合法 JSON，或某项写错）不会退出，否则 launchd 只会一遍遍悄悄重启它。它在日志里写一行原因，5 秒后再读，之后每次等的时间翻倍，最多 5 分钟；改好后照常拉起宿主。坏着的时候宿主也起不来，所以只要还读得出 `telegram.allowedUserIds`、`secretsFile` 和 bot token，它发一条 `🔔 ⚠️ config.json 读不了：<原因>。改好后看门狗会自己拉起宿主`，响铃，原因去掉密钥。连这几项都读不出（比如整个文件不是合法 JSON）时只记日志。改好后不另发 ✅。看门狗已经在跑时改坏了 `config.json`，它用的还是启动时读到的配置，宿主停了或起不来时按上面两条报。
- **网页。** 宿主启动时读 `outage.json`，横幅的「最近恢复」里列一条 `宿主停了约 N 分钟（几点起）`，一小时后消失。停机期间网页本身打不开，所以只能事后看到。

看门狗直接调 Telegram 的 `sendMessage`，不经过宿主，也不收消息（不调 `getUpdates`），所以不会和宿主的 Telegram 客户端抢消息。bot token 和收消息的人跟宿主读的是同一处：`secretsFile` 或环境变量里的 `TELEGRAM_BOT_TOKEN`，`config.json` 的 `telegram.allowedUserIds`。没写 `telegram` 段时只记日志。读不到 token 时看门狗记一行日志，照样重启宿主。

发不出去时（断网、Telegram 出错），看门狗在日志里记一行，一分钟后再试，按顺序补发；重启宿主不等它。Telegram 拒绝某个聊天时（403，比如这个人从没给 bot 发过消息），这条记一行日志后放弃。补发的消息只在看门狗进程里，看门狗自己重启时没发出去的就丢了。

刚拉起、还没被看门狗的一次检查看到在跑就又死掉的宿主，算一次启动失败，不算「宿主停了」。

## 整台机器离线

Mac 关机、断电、断网时，宿主和看门狗都在这台机器上，谁也发不出消息。这种情况只能从外面发现，**现在没有做**。

可选的做法：注册一个免费的外部心跳检查服务（dead man's switch 一类，比如 Healthchecks.io 的免费档），拿到一个专属网址；看门狗每分钟请求一次这个网址，几分钟没收到请求，服务就经它自己的渠道（邮件、Telegram 等）通知你。要做的话，账号由你自己注册，网址放进 `secretsFile`，看门狗这边只需加一个定时请求。

## 什么时候拉响

| 断的是什么 | 编号 | 什么时候亮 | 什么时候灭 |
| --- | --- | --- | --- |
| 幕僚长的模型出错（5xx、太忙、连不上） | `model:router` | 连着 `modelFailuresBeforeAlarm` 轮失败（默认 2） | 下一轮成功 |
| 幕僚长的模型 401、403、登录失效 | `model:router` | 第一次 | 下一轮成功 |
| 幕僚长的主模型限流，切到了回退模型 | `model:router:fallback` | 切换时 | 主模型试探成功、切回主模型 |
| 回退模型也限流 | `model:router` | 第一次 | 下一轮成功 |
| 助手（所有 Worker 合在一起）的模型，同上三种 | `model:worker`、`model:worker:fallback` | 同上 | 同上 |
| 回退模型今日用量到了 `fallbackDailyTokens` | `model:fallback-cap` | 有任务因此受阻时 | 用量又在上限以下时 |

一轮失败指 Pi 自己的重试（`retryAttempts`）都用完之后这一轮仍是错误。宿主只记在内存里：重启后还没修好的，下一次失败时再亮、再发一次。

## 调阈值

`config.json` 里写，两项都可以省略：

```json
{ "health": { "modelFailuresBeforeAlarm": 2, "feedFailuresBeforeAlarm": 3 } }
```

`feedFailuresBeforeAlarm` 给模块来源用，见「模块的来源」。必须是 1 以上的整数，写错了宿主不启动，报错指出是哪一项。

## 错误文字

横幅和 Telegram 上的错误是一行，最多 200 个字，网址里的 `key=`、`token=` 等参数值、`Bearer` 后面的值和 `sk-` 开头的密钥都换成 `…`。

## 模块的来源

每个模块 feed 一个警报，编号 `data:<模块>/<feed>`，网页上写成「<模块标题> <feed 标题>」，例如「测试信箱 来信」。

| 情况 | 什么时候亮 | 什么时候灭 |
| --- | --- | --- |
| handler 抛错、超时、输出不对 | 连着 `feedFailuresBeforeAlarm` 拍（默认 3） | 下一拍成功 |
| handler 的错误是 401、403、invalid_grant 这类鉴权错误 | 第一拍 | 下一拍成功 |
| feed 自己报了 `problem`（比如 stock-ta 没设密钥、连着 5 轮取不到报价），没带 `once` | 第一拍，横幅上的错误就是 feed 写的那句 | 哪一拍不再报 |
| 模块被关掉、模块包被删掉、feed 被拿掉 | 悄悄撤下，不发 ✅ | |

收件箱类的 feed 一件东西最多试三次。试的这几次不算进连着失败：三次都没成，这一件放进 `rejected`，宿主写一条「通知」，Telegram 上一条 🔔，不亮警报，也不发 ✅。只有鉴权错误照上表第一拍就亮，因为它修好之前每一件都会失败。

**只有坏了、修好之前一直坏着的才亮警报。** 没设密钥、授权失效、接口挂了、报价过期、扫描失败、邮件名单是空的（配置坏了）都亮，一直红着。一次性的消息，下一拍就不再报的，比如邮件的「有 N 小时没查」（宿主停过一天，补了最近一天的信），feed 在 `problem` 上写 `once: true`：宿主只写一条「通知」，Telegram 上是一条 🔔，不亮警报，也不发 ✅，免得你先收到 ⚠️、一分钟后又收到 ✅。这一拍同时算成功的一拍，原来亮着的警报照样解除。模块作者怎么写见 `docs/modules/module-user-guide.md` 的「feed 报问题」。

模块工具现查失败（比如问价时 `quote` 连不上）不算进警报：失败写在回答里，你当场就看到了；交易时段报价 feed 每分钟都在取同一家，断了会从 feed 那里响。见 ADR-0026。
